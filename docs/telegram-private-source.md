# مصدر Telegram خاص — حصاد اليوم

يقرأ الناشر منشورات القناة الخاصة عبر بوت مصدر منفصل، ثم يمرر نص المنشور الخام إلى مسار النشر الحالي في `hasad_news_bot_fixed.py`. لذلك تُطبّق عليه تعليمات إعادة الصياغة الحالية، فلاتر الكلمات والتكرار، الفئة `أخبار وتقارير`، وحفظ المقال في Supabase بالطريقة نفسها المستخدمة مع الفيدات.

## الإعداد

أضف الإعدادين التاليين إلى إعدادات Actions في المستودع، ولا تضع القيم في الملفات أو السجلات:

- `TELEGRAM_SOURCE_BOT_TOKEN`: توكن بوت القراءة `@moieen2017mbot` (Repository secret).
- `TELEGRAM_SOURCE_CHAT_ID`: معرّف قناة المصدر (Repository variable مفضل؛ يقبل Workflow أيضًا الاسم نفسه كـ Repository secret احتياطيًا).

يجب أن يكون بوت المصدر مشرفًا في قناة المصدر. يبقى `TELEGRAM_BOT_TOKEN` منفصلًا ويُستخدم فقط لإرسال المقالات المنشورة إلى قناة حصاد الحالية.

المسار المجدول يمرر إعدادَي المصدر إلى خطوة النشر مع متغيرات Supabase الموجودة مسبقًا. يتحقق البرنامج من عضوية بوت المصدر قبل polling، ويحذف أي webhook قائم مع الإبقاء على التحديثات المعلقة، ويتابع من مؤشر `update_id` المحفوظ في `public.bot_source_cursors`.

## الصور والمؤشر

عند وجود صورة، ينزّل البوت أكبر حجم متاح (حتى حد Bot API المستضاف 20MB)، ثم يستخدم خط صور حصاد الحالي: فحص الشعارات المحظورة، ضغط WebP، إنشاء صورة مصغرة، ورفعها إلى Supabase Storage. إذا تجاوزت الصورة حد التنزيل، ينشر النص بلا صورة. أما إذا تعذر تنزيل صورة ضمن الحد بسبب خطأ عابر، فيترك المؤشر دون تحديث حتى يعيد التشغيل معالجة المنشور.

مخطط الجدول موجود في `supabase/migrations/20260925195000_create_bot_source_cursors.sql`. هذا الترحيل طُبّق على مشروع Supabase الخاص بحصاد.
